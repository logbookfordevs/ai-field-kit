# Command reference

Use these commands for the common setup loop. Run any command with `--help` for its complete current options.

<h2 id="reference-core">Core commands</h2>

| Command | Purpose |
| --- | --- |
| `afk setup` | Guided setup across selected areas. |
| `afk setup <area>` | Run one area: rules, skills, profiles, agents, mcps, tools, or hooks. |
| `afk sync --preset <id>` | Refresh the catalog and update installed members of a preset. |
| `afk show [category...]` | Inspect cached catalog data without changing it. |
| `afk refresh [category...]` | Update cached catalog files. |
| `afk sources list` | List the saved default and favorite sources. |
| `afk doctor` | Validate all local catalog manifests. |
| `afk preset [id]` | Choose or apply a catalog setup bundle. |
| `afk skills list` | Inspect the shared global library; choose other roots with flags. |

<h2 id="reference-flags">Setup flags</h2>

<dl>
<dt><code>--dry-run</code></dt>
<dd>Print planned actions without applying them.</dd>
<dt><code>--local</code></dt>
<dd>Use project setup scope. On <code>refresh</code>, target <code>./afk/catalog</code>.</dd>
<dt><code>--agent &lt;agent&gt;</code></dt>
<dd>Override detected targets; repeat for more than one.</dd>
<dt><code>--source &lt;source&gt;</code></dt>
<dd>Use a catalog source for this command only.</dd>
<dt><code>--yes</code></dt>
<dd>Accept defaults and skip prompts; best after a source is saved.</dd>
<dt><code>--verbose</code></dt>
<dd>Show delegated installer output.</dd>
</dl>

<h2 id="reference-catalog-editors">Edit other catalog families</h2>

Run `afk rules catalog`, `afk agents catalog`, `afk mcps catalog`, `afk tools catalog`, or `afk hooks catalog` to open that family’s editor. Each supports `add`, `edit`, and `remove`; MCPs, tools, and hooks also support `toggle-default`. Edits target the global cache unless you add `--local`. Catalog removal changes a definition, not an existing installation.

<h2 id="reference-presets">Apply a preset bundle</h2>

```bash inspect and choose a preset
afk show presets
afk preset --dry-run
```

A preset groups setup areas and can select exact members or every item in its declared areas. `afk preset <id>` skips the preset menu; `afk setup preset` is the long form. Presets route installation, while skill profiles manage working sets after installation.

<h2 id="reference-sync">Update a preset environment</h2>

Use `afk sync` to keep an existing global environment aligned with a preset. It refreshes the catalog from your remembered source, then updates that preset's installed members. Run `afk sync` to choose a preset interactively, or name one directly:

```bash preview and apply preset updates
afk sync --preset <id> --dry-run
afk sync --preset <id> --yes
```

Replace `<id>` with a preset ID from `afk show presets`. The preview fetches fresh definitions and shows planned work without writing the catalog cache or changing installed components. Supply `--preset` outside an interactive terminal. `--yes` skips AFK prompts; delegated updaters may still prompt.

### What gets updated

| Part | Update behavior |
| --- | --- |
| Skills | Reinstalls selected skills through `skills add` using the refreshed catalog source, preserving disabled status. `afk skills update` instead follows installed lock metadata. |
| Tools | Runs each installed tool's cataloged update command. Tools without one are skipped. |
| Rules | Uses the rules setup flow to refresh AFK-managed regions and declared reference files, preserving content outside those regions. |
| MCPs | Reapplies named server configurations through `add-mcp`. Server software updates depend on the configured source or launcher. |
| Hooks | Installs or refreshes scripts and their registration. |
| Custom Agents | Installs or regenerates native agent definitions. |
| Profiles | Refreshes definitions without enabling profiles or installing their packages. |

### Missing members and source changes

New preset members are installed automatically. When the preset includes skills, every catalog skill without `imported: true` is installed in batches by source, regardless of defaults or preset skill selections; existing disabled skills stay disabled. Rules sync once across selected harnesses.

To include imported catalog skills in the same installation batches:

```bash include extra tracked skills
afk sync --preset <id> --include-extra-skills --yes
```

Sync reuses the selection from `afk setup skills --all --exclude-imported --yes`; `--include-extra-skills` removes that exclusion. Uncataloged skills are untouched. Profile definitions refresh without enabling profiles or installing their packages. Sync preserves local-only catalog entries and never uninstalls components removed upstream. Incoming definitions replace matching catalog IDs, so a skill's source can change on the next sync.

Use `--source <source>` for a one-run catalog source override and `--agent <agent>` to limit agent targets. Sync supports global environments only. Tools are detected by executable availability on `PATH`; missing tools are installed. Skill selection follows each catalog entry’s installer arguments, as in setup. The former `--install-missing` flag remains accepted for compatibility but is unnecessary.

If an update fails, independent updates continue and the final summary reports failures with a nonzero exit code. Review that summary before retrying. To update the AFK CLI itself, use `afk update`.

<h2 id="reference-tool-updates">Update cataloged tools</h2>

```bash preview tool updates
afk tools update --dry-run
```

Select tools with cataloged update commands, or pass their IDs directly with `afk tools update <tool...>`. Remove `--dry-run` to run the selected commands. This updates those tools; `afk update` updates AFK itself.

<h2 id="reference-utilities">Discover UI skills and maintain AFK</h2>

`afk ui categories`, `afk ui list --category motion`, and `afk ui get <skill>` delegate to UI Skills. `get` prints skill content without installing it. `afk open` opens the user AFK folder; add `--code` for VS Code. `afk update --dry-run` previews the hosted release installer; `afk update` runs it.
