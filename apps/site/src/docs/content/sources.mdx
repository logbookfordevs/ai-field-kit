# Save sources. Share stacks.

**Sources & Stacks** keeps the repositories and skill selections you want to reuse.
Browse Sources & Stacks as cards by default, or choose **List** for a compact view.
Both views retain the same selections and actions.

A source bookmarks one repository. A stack combines selected skills from several
original repositories into one named, portable install plan.

Both are shared across your projects. Saving, importing, refreshing or removing
one does not install skills or change profile activation.

<h2 id="save">Save a source</h2>

1. Choose **Add source** and enter a name and repository reference. Repository URLs,
   SSH URLs and `owner/repository` references are supported.
2. Keep **All skills**, or choose **Choose skills → Find skills** to pick individual
   members from that repository.
3. Review the selection and choose **Save bookmark**.

The picker supports search by skill name, description and repository folder.
When discovery provides folder paths, expandable folders show where each skill
comes from. Filtering keeps your selected members, even when they are hidden
from the current search.

**All skills** copies a command that opens Skills CLI’s skill picker, so you can
choose members when running it. The app’s **Install** action also lets you choose
members for that run without changing the bookmark. **Choose skills**
keeps an explicit selection: new upstream members do not join it automatically.
Changing the repository reference clears its old selection so you can choose again.

**Create profile** opens a new profile draft with the source name, repository
and saved selection. For **All skills**, AFK discovers and selects every current
member first. Review or adjust the members, then save to prepare missing skills
without enabling the profile. The source bookmark remains unchanged; later source
edits and new upstream skills do not automatically change the profile.

Use **Edit** to change the bookmark or **Remove bookmark** to stop saving it.
Removing a bookmark leaves installed skills alone. The source reference remains
visible below its name for normal text selection and copying.

For an **All skills** bookmark, **Install** discovers the repository’s skills and
opens the searchable folder picker. Select individual members or **Select all**
before starting. Bookmarks with saved selections and stacks keep their explicit
member lists.

<h2 id="copy">Copy installation commands</h2>

- **Copy install command:** one source, opening the skill picker for **All skills** bookmarks or passing the saved explicit selection.
- **Copy all sources script:** every saved source bookmark, in sequence, respecting
  each bookmark's selection. This does not include saved stacks.
- **Copy install script** on a stack: that stack's selected skills, grouped by source.

Choose the installation destination and optional agent before copying. Those
choices affect the generated commands, not where bookmarks or stacks are saved.

Run the copied text in your terminal when you are ready. Skills CLI performs the
installation. Copying does not execute anything or change installed skills.

<h2 id="install">Install from AFK</h2>

Each source and stack also has an **Install** button. Choose the destination,
open Install, and select an agent target. AFK runs Skills CLI with your saved
skill selection and shows progress and command output. The copied commands
retain their interactive behavior.

Closing the dialog leaves installation running. Reopen Install to see its
progress or result, or choose **Cancel installation** to stop it. Completed
installations and any partial files are kept.

Installation can replace existing skills and make them available. To update
existing skills while preserving disabled state, use **Update skills** in
Installed Skills instead.

<h2 id="stacks">Create a stack from selected sources</h2>

A stack is useful when your preferred skill set spans several repositories.
For example, you can keep a handful of design skills from one source and a few
browser-testing skills from another, then share one install plan.

1. Save the sources you want to reuse, with either **All skills** or **Choose skills**.
2. Choose **Create stack**. Enter a name, a stable identifier and an optional description.
3. Select sources to include. For an **All skills** bookmark, use **Choose skills**
   to pick members in the searchable folder tree. Then choose **Review stack**.
4. Check the original repository references and selected skills before saving.

Every saved source appears in stack creation. Each stack group needs an
explicit skill list so the saved plan does not silently expand when upstream adds
new skills. Saving a stack captures those choices; later bookmark edits do not
rewrite the stack.

Expand **Skills by source** to inspect a saved stack. Use **Edit** to change its
manifest, **Export JSON** to share it, or **Remove stack** to remove the saved plan.
None of those actions uninstalls skills.

<h2 id="import">Import a shared stack</h2>

Choose **Import stack**, then either paste the manifest JSON or enter a direct
HTTPS URL to its JSON file. Choose **Review stack**, inspect its source groups and
selected skills, and save the reviewed plan.

For GitHub, use the raw JSON file URL rather than the repository's HTML file page.
Use the final URL directly; redirects are not accepted. AFK fetches only the
manifest at this step, not its skill repositories.

A stack imported from a URL retains that URL as its origin. A pasted or locally
created stack has no remote origin. Each source group still points to its original
repository; the manifest URL does not replace those installation sources.

<h2 id="refresh">Review manifest updates</h2>

A stack with a saved origin offers **Refresh manifest**. This fetches a new proposed
manifest and shows a comparison with your saved name, description, sources and
skill selections. Review it before applying the replacement. Your current stack
and local edits remain until you accept it.

Refreshing a manifest does not update installed skills. Use **Install** or copy its installation
script if you want to install the revised selection. Use Installed Skills for
package updates.

<h2 id="manifest">Publish a stack manifest</h2>

**Export JSON** produces a versioned manifest you can store in a repository or
share directly. Version 1 includes:

- `version`: `1`.
- `id` and `name`: a stable identifier and display name.
- `description`: optional context for the selection.
- `sources`: ordered groups, each with a `name`, original `source` reference and
  nonempty `skills` list of explicit skill names.

Stacks contain selections, not shell commands. Wildcards and unknown fields are
rejected. Keep original source references intact, and review duplicate skill names
across repositories because installation names may collide.

For publisher details, see the [manifest contract](https://github.com/logbookfordevs/ai-field-kit/blob/main/docs/skill-stacks.md),
[JSON Schema](https://github.com/logbookfordevs/ai-field-kit/blob/main/docs/schemas/skill-stack.v1.schema.json)
and [example manifest](https://github.com/logbookfordevs/ai-field-kit/blob/main/docs/examples/skill-stack.v1.json).

<h2 id="group">Choose a stack or a profile</h2>

Use a **source** for one repository bookmark and a **stack** for a portable
installation selection across repositories. Neither has an enabled state.

Use a [profile](/docs?chapter=profiles) when you want a selected group prepared
locally for enabling, disabling or reading with your agent. Saving a stack does
not create a profile, and installing its skills does not activate a profile.

<h2 id="updates">Update from Installed Skills</h2>

Use **Update skills** in [Installed Skills](/docs?chapter=skills#update).
AFK runs Skills CLI in an isolated workspace and preserves availability and
invocation preferences when applying updates. This only updates installations
Skills CLI tracks. Source discovery and manifest refresh
are separate from installed-package updates.
