# Prepare once. Activate by target.

Profiles are shared groups of skills. Demo Studio and Global can use the same definition without sharing activation state.

<h2 id="create">Create a shared group</h2>

Open **Profiles → Create profile**. Use one repository source or select existing Global skills. Review the members, select what you need, and save.

Repository preparation delegates to Skills CLI in an isolated workspace. Selected missing copies are retained under:

```text Shared disabled storage
~/.agents/skills/.disabled/<skill>/
```

<div className="docs-callout"><strong>What creation changes</strong><p>A profile currently stores one source reference. Already available skills stay available; creating a group does not turn them off. Missing selected copies are prepared disabled.</p></div>

Skills are identified by name. Two repositories with the same skill name do not get separate storage namespaces. Inspect existing members before reusing names from another source.

<h2 id="enable">Enable for a project</h2>

Add the project’s folder in **Settings** first. Then choose its name in the profile’s **Enable for** selector and click **Enable**.

Changing the dropdown only changes the target shown. It does not activate anything. Global and project activation are independent; more than one profile can be enabled in the same target.

<h2 id="physical">Understand the physical change</h2>

Project activation exposes shared copies through AFK-owned links:

```text Project discovery links — schematic paths
<project>/.agents/skills/<skill>
<project>/.claude/skills/<skill>
```

No second download is needed. Global activation uses:

```text Global discovery links
~/.agents/skills/<skill>
~/.claude/skills/<skill>
```

Existing active skills can remain in their original location. Supported project invocation overrides use an isolated copy instead; see [Settings & storage](/docs?chapter=settings#storage).

<h2 id="disable">Disable without breaking another group</h2>

Disable withdraws only AFK-owned exposure in the chosen target. Stored skill files remain ready.

| Other owner | What happens |
| --- | --- |
| Another enabled profile needs the member | Its exposure is kept. |
| The member is enabled independently | Independent availability is preserved. |
| A user file already existed at the path | It is not removed merely because the profile names it. |

The project inventory excludes global-only entries. An agent may still discover Global skills while working in a project.

<h2 id="read">Read with your agent</h2>

**Read group once** opens instructions and a copyable command using the profile’s actual ID:

```bash Use the ID copied by AFK
afk profiles use <profile-id>
```

It prints locally prepared member instructions and resource directories without changing activation. There is no remote fetch during invocation, automatic slash-command registration, or injection into another chat. [Follow the complete flow](/docs?chapter=agent).

<h2 id="edit">Edit or remove</h2>

Disable the profile in every target first. Editing can prepare new selected members. Removing deletes its definition, not stored skill files. If preparation fails, the profile is not saved as ready; already prepared copies remain available for retry.

<h2 id="missing">Restore missing members</h2>

You can delete stored members while their profiles are disabled. The profile keeps
its selection. Enabling a repository-backed profile prepares missing members from
its saved source before making them available. If preparation fails, the profile
stays disabled. A local-only profile has no download source: restore its missing
files or edit its members before enabling it. Profiles enabled in any scope still
protect their members from deletion.
