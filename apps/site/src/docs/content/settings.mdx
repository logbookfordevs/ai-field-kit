# One folder. Local paths.

Definitions can travel between machines. Skill copies and project folders remain local.

<h2 id="location">Choose where settings live</h2>

Default: `~/.afk/settings.json`. The **AFK folder** keeps `settings.json`, your canonical `AGENTS.md`, and `references/` together. Choose a repository, Drive or iCloud folder if you want your storage provider to sync these files. A local pointer at `~/.afk/settings-location.json` remembers where the configuration lives.

**Choose folder** opens a folder browser. Create a dedicated AFK subfolder, move your current AFK files into a new location, or load an existing folder containing `settings.json`. Moving copies the configuration and Markdown, keeps the original folder, and refuses to overwrite existing files. Loading another configuration requires disabling active skills and profiles and disconnecting synced rule destinations first. Neither action syncs agent files.

A launch override takes precedence over the local pointer:

```bash Optional launch override
AFK_SETTINGS=/path/to/settings.json afk
```

The portable JSON holds profile definitions, project paths, tool commands, source
bookmarks, stack manifests and optional origins, and manually saved skill lists.
Activation, readiness, invocation preferences and ownership receipts are stored
separately on this machine. Saved skill lists carry the availability and invocation
choices captured when you saved them. Use the UI for changes so configuration and
filesystem operations agree.

<h2 id="projects">Add a project folder</h2>

Choose **Add project**, navigate from your home folder, select **Use this folder**, then name the project. This defines a target; activation stays in **Profiles**.

Renaming preserves its target relationships and preferences. Disable its profiles before changing the folder.

If a project path is missing on this machine, Settings shows **Project folder missing**.
Choose another folder to reconnect it, or remove the saved project entry. AFK does
not copy, clone or download project files.

<h2 id="import">Import intentionally</h2>

1. Disable currently enabled profiles before replacing configuration.
2. Choose the JSON file and review or remap project folders.
3. Import. Profiles start unprepared and disabled; local link receipts and individual activation are cleared.
4. Use **Install profile skills** for the profiles you want, then enable each desired target explicitly. Restore individual saved skills from **Installed Skills → Saved skills** after review.

<div className="docs-callout"><strong>Import does not execute setup</strong><p>Saved tool commands do not run. Saved skill choices are applied to local files only when you explicitly restore selected entries.</p></div>

Your provider owns sync and concurrent-file conflict handling. AFK does not automatically apply another machine’s activation or sync downloaded skill files.

<h2 id="storage">Know what stays on disk</h2>

New selected repository members are stored under `~/.agents/skills/.disabled/<skill>/`. Global and project activation expose them through owned links in `.agents/skills/` and `.claude/skills/`.

A project invocation override uses `<project>/.agents/skills/.afk-overrides/<skill>/`. Reset reconnects owned links to the shared copy. Physical project-local skills keep their own original metadata.

Existing available skills may remain in place. Profile disable removes only owned exposure, preserving other profiles, independent availability, and preexisting files.

<h2 id="export">Export configuration</h2>

**Export AFK folder · ZIP** includes settings, canonical rules and references. Import previews the contents and asks which local destination files to connect; it does not sync them. Review project folder mappings too.

The separate **Settings only · JSON** controls export or import configuration without rule content. The terminal alternative writes a new file and refuses to overwrite an existing export:

```bash Export current configuration
afk settings export /path/to/export.json
```

Export includes definitions and saved skill lists, but excludes local activation, readiness and ownership receipts. Project paths travel as references; review their mappings on the new machine. Skill files and project files are not included.
